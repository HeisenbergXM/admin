```

### 1.2 字段表列含义

| 列 | 含义 |
|----|------|
| 字段 | 页面上的字段标签 |
| 控件 | 输入控件类型（文本框/下拉/日期/只读文本/复选等） |
| 必填 | ●=必填，○=选填，—=只读不可编辑 |
| 校验 | 前端校验规则（后端仍会二次校验） |
| 数据来源 | 取值来源：用户输入 / 字典(dict) / 主数据下拉 / 接口回填 / 系统生成 |

### 1.3 控件与数据来源约定

- **字典下拉**：值来自系统管理 → 字典管理，前端通过字典编码拉取选项（如 `sales_status`、`payment_status`、`delivery_status`、`drosstech_status`、`invoice_status`）。
- **主数据下拉**：值来自主数据管理（车型 `t_md_model`、外饰色 `t_md_exterior_color`、内饰色 `t_md_interior_color`、经销商 `t_md_dealer`），支持按关键字搜索，仅显示「启用」项。
- **车辆基本信息**（车型/外饰色/内饰色/车型年）：在涉及车辆的列表、明细、挂载选择处只读展示，实时取自主表与主数据，**不可在该页编辑**。
- **审计信息**（创建人/时间、修改人/时间、确认人/时间）：在详情页只读展示，由后端写入。

## 2. 全局交互范式（贯穿所有业务页面）

所有阶段业务页面共享同一套交互骨架，前端可抽象为通用组件。

### 2.1 「草稿 → 确认」两步范式

```
进入阶段页 ──► [保存草稿] ──► 记录 draft（可反复改） ──► [确认] ──► 二次弹窗确认 ──► confirmed（锁定）
                  ▲                                                              │
                  └──────────────── 草稿态可继续编辑 ◄────────────────────────────┘   推进生命周期到下一阶段
```

- **草稿态（draft）**：字段可编辑，显示 `[保存草稿]` 与 `[确认]` 两个按钮。
- **已确认态（confirmed）**：所有业务字段变为只读，`[保存草稿]`/`[确认]` 隐藏，仅保留返回/查看；页面顶部显示「已确认 · 确认人 · 确认时间」标记。
- `[确认]` 点击后必须弹二次确认框（提示"确认后不可修改"），用户再次确认才提交。

### 2.2 卡控与按钮可用性

- 前置阶段未确认时，本阶段入口（菜单/列表行操作按钮）**置灰禁用**，hover 显示原因提示（如"需先完成车辆录入确认"）。
- 卡控以后端为准；前端禁用仅为体验优化，提交仍可能被后端拦截并返回业务异常，需弹错误提示。
- 已确认记录再次进入显示只读详情，不提供编辑/重复确认入口。

### 2.3 生命周期状态徽标（全局统一配色建议）

| 状态码 | 中文 | 建议色 |
|--------|------|--------|
| PENDING_OFFLINE | 草稿（新录入） | 灰 |
| PENDING_INBOUND | 待入库 | 蓝 |
| PENDING_ALLOCATION | 待分配 | 蓝 |
| PENDING_INVOICE | 待开票 | 橙 |
| PENDING_PAYMENT | 待收款 | 橙 |
| PENDING_DELIVERY | 待配送 | 青 |
| PENDING_REGISTRATION | 待上牌 | 青 |
| COMPLETED | 已完结 | 绿 |

> 状态徽标在车辆列表、各阶段列表、全景视图统一使用同一组件与配色。

### 2.4 列表页通用规范

- 顶部查询条（多条件，可折叠）+ 中部数据表格（分页）+ 行操作列。
- 分页默认每页 20 条，支持页码跳转与每页条数切换。
- 空态显示占位插画 + "暂无数据"文案；加载态显示骨架屏或 loading。
- 业务列表页**不提供导出**（仅车辆全景视图可导出）。

│ ├─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─┤ │

**字段表**

| 字段 | 控件 | 必填 | 校验 | 数据来源 |
|------|------|------|------|----------|
| VIN | 文本框 | ● | 非空、唯一（失焦异步查重，重复则报错并禁止保存） | 用户输入 |
| 车型 | 下拉(可搜索) | ● | 非空 | 主数据 t_md_model |
| 外饰颜色 | 下拉(可搜索) | ● | 非空 | 主数据 t_md_exterior_color |
| 内饰颜色 | 下拉(可搜索) | ● | 非空 | 主数据 t_md_interior_color |
| 发动机号 | 文本框 | ● | 非空 | 用户输入 |
| 车型年 | 文本框 | ○ | 年份格式 | 用户输入 |
| 物料 | 文本框 | ○ | — | 用户输入 |
| Shipment | 文本框 | ○ | — | 用户输入 |
| Batch | 文本框 | ○ | — | 用户输入 |
| Offline EPMB 日期 | 日期选择 | ○ | 日期格式 | 用户输入 |
| EPMB ok 日期 | 日期选择 | ○ | 日期格式 | 用户输入 |
| 备注1 | 多行文本 | ○ | 长度限制 | 用户输入 |

**三态行为**

- **新增/草稿态**：全部字段可编辑；`[保存草稿]` 创建/更新主记录（`lifecycle_stage=PENDING_OFFLINE`）并停留在表单（或返回列表，提示"已保存草稿"）；`[确认]` 弹二次确认 → 提交成功后阶段变「待入库」，字段转只读。
- **确认态/详情态**：所有字段只读；隐藏 `[保存草稿]`/`[确认]`；顶部显示阶段徽标 + 确认人/确认时间；底部仅 `[返回]`。

**校验与提示**

- VIN 查重失败：输入框下方红字"该 VIN 已存在"，`[保存草稿]`/`[确认]` 禁用。
- 必填项未填点确认：定位到首个错误字段并标红。
- 确认成功：toast"车辆录入已确认，已进入待入库"，返回 P1。

**流转**：确认成功后该车进入 P2.1 运输单可选 VIN 候选池。

**用途**：维护运输单表头与 VIN 明细，逐车填 SAIC buy off，整单确认后单上所有 VIN 一并「待入库→待分配」。

│ 运输单 / 新建                                单据状态：●草稿              │
├───────────────────────────────────────────────────────────────────────┤

│ ├─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─┤ │
│  VIN 明细                                              [＋ 添加 VIN]      │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │VIN        │车型    │外饰色│车型年│SAIC buy off日期 *│操作          │   │
│  │LSJW...001 │MG4 EV  │黄   │2024 │[📅__________]     │[移除]        │   │

│  └─────────────────────────────────────────────────────────────────┘   │
├───────────────────────────────────────────────────────────────────────┤

```

**表头字段**

| 字段 | 控件 | 必填 | 校验 | 数据来源 |
|------|------|------|------|----------|
| 运输单号 | 文本框 | ○ | 留空则系统生成 | 系统生成/用户输入 |
| 到仓库日期 | 日期选择 | ● | 非空（整单共享，回填各 VIN） | 用户输入 |
| 备注2 | 多行文本 | ○ | — | 用户输入 |

**VIN 明细行字段**

| 字段 | 控件 | 必填 | 校验 | 数据来源 |
|------|------|------|------|----------|
| VIN | 只读文本 | — | — | 添加时选择 |
| 车型/外饰色/车型年 | 只读文本 | — | — | 主数据(随VIN带出) |
| SAIC buy off 日期 | 日期选择 | ● | 整单确认时每行必填 | 用户输入(逐车) |

**[＋ 添加 VIN]**：弹出候选选择器，**候选仅 `PENDING_INBOUND` 且未被其它运输单占用的车辆**；支持按 VIN/车型搜索、多选加入。

```
   ┌── 选择 VIN（候选：待入库 & 未占用）────────────────┐
   │ 搜索[＝____]                                       │
   │ ▢ LSJW...001  MG4 EV  黄  2024                     │
   │ ▢ LSJW...005  MG4 EV  白  2024                     │
   │ ☑ LSJW...004  ZS EV   红  2023                     │
   │                              [取消]  [加入所选(1)] │
   └──────────────────────────────────────────────────┘
```

**三态/按钮行为**

- **草稿态**：可增删 VIN、改表头、逐车改 SAIC buy off；`[保存草稿]` 保存。
- **[整单确认]**：弹二次确认（显示"将确认 N 辆车入库，确认后单据锁定"）；提交前前端校验每行 SAIC buy off 已填，否则标红阻止。成功后单据与明细只读，单上所有 VIN 阶段→`PENDING_ALLOCATION`。
- **已确认态**：全只读，仅 `[返回]`。

**异常**：若某 VIN 已被其它单占用/状态已变，后端返回冲突 → 弹错误并高亮冲突行，需移除后重试。

**流转**：确认后这些 VIN 进入 P4 车辆销售可操作范围。

## 9. 前端开发注意事项（汇总）

1. **通用组件优先**：列表页（查询条+表格+分页+空态）、阶段表单（草稿/确认/详情三态）、确认二次弹窗、VIN 候选选择器、状态徽标——均建议抽象为可复用组件。
2. **状态驱动按钮**：所有操作按钮的显隐/禁用由「车辆生命周期阶段 + 记录 draft/confirmed」共同决定，集中在一处映射，避免散落判断。
3. **前后端双校验**：前端校验仅为体验；确认/提交后须处理后端返回的业务异常（阶段冲突、VIN 被占用、缺正式发票等），统一弹错误并高亮问题项。
4. **候选数据动态拉取**：运输单/经销商行的 VIN 候选随生命周期变化，每次打开选择器实时拉取，不缓存。
5. **车辆基本信息只读联动**：选 VIN 后带出车型/颜色/车型年，仅展示不入库。
6. **导出唯一入口**：仅 P8 全景视图有导出；其余页面不得出现导出按钮。
7. **字典与主数据**：下拉项统一走字典/主数据接口，不在前端硬编码；仅显示启用项。

## 10. 验收要点（页面层面）

- 五大核心模块页面均可按本稿布局与字段实现，控件类型、必填、校验与数据来源一致。
- 「草稿可改 → 确认锁定」三态在每个阶段表单正确表现；确认弹二次确认且不可逆。
- 生命周期卡控在前端正确体现：前置未确认时后续入口禁用并有提示。
- 运输单整单确认、经销商行按行签收确认的批量推进交互正确。
- 形式发票场景：开票→（转正）→收款的入口禁用/解锁逻辑正确。
- 车辆全景视图仅业务主管可见、可导出，发票分区展示两组记录。
