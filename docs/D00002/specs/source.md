# 需求来源说明 — D00002 车辆全生命周期管理系统 · 前端页面设计

## 来源

- 上游需求：`.cx/D00001/specs/design.md`（车辆全生命周期管理系统 VLM 设计文档，已定稿待批准）
- 本规范是 D00001 的**前端页面设计派生件**，不改变 D00001 的业务逻辑、数据模型与卡控规则，仅将其翻译为面向前端开发的页面布局、字段、交互与流转说明。

## 目标

为前端开发提供一份文字版页面设计稿，使其无需阅读后端数据模型即可：

- 了解每个核心业务功能对应哪些页面、页面的区域布局（线框图）
- 知道每个页面上有哪些字段、控件类型、是否必填、前端校验、数据来源（接口/字典/主数据）
- 理解页面之间如何跳转、各操作触发的状态流转与按钮可用性卡控
- 把握"草稿可改 → 确认锁定 → 推进生命周期"这一贯穿全系统的交互范式

## 范围（本期）

- **覆盖**：生产管理、运输管理、销售管理、财务管理、车辆全景视图五大核心业务模块的页面设计
- **不覆盖**：登录页与全局布局框架（顶栏/侧边菜单/面包屑）由前端按惯例实现；系统管理（用户/角色/菜单/字典）与主数据管理走通用 CRUD，不在本稿展开
- **呈现形式**：每页 ASCII 低保真线框图 + 字段表（字段/控件/必填/校验/数据来源）+ 交互与流转说明

## 关键约束（继承自 D00001）

1. 生命周期严格按序卡控，前置阶段未确认则后续入口禁用（前端置灰 + 后端二次校验）。
2. 每阶段"录入/暂存（draft）→ 确认（confirmed）"两步；确认后锁定不可改、不可重复确认。
3. 物流为单据驱动批量操作：车厂到仓库用运输单（整单确认），仓库到经销商用发车清单→行车路单→经销商行（按经销商行签收确认）。
4. 各阶段涉及车辆处除 VIN 外可显示车型/颜色/车型年，实时取主表与主数据，不冗余存储。
5. 除车辆全景视图（仅业务主管，可导出）外，所有功能仅提供列表查询，不提供导出。
