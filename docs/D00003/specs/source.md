# 需求来源说明 — D00003 运输管理改造（按 VIN 单车维护物流信息）

## 来源

- 派生自 [D00001 车辆全生命周期管理系统](../../D00001/specs/design.md)（运输管理章节 4 / 6.5 / 7.4）
- 客户口述需求（本次会话）

## 背景

D00001 的运输管理采用「单据驱动批量流转」：

- **车厂 → 中转仓库**：用 **运输单**（1 单 N 车）+ 明细，整单确认后所有 VIN 一并入库。
- **中转仓库 → 经销商**：用 **发车清单 → 行车路单 → 经销商行**（三层）+ 经销商行下挂 VIN，按经销商行确认签收。

现业务反馈：单据式流程偏重，实际更希望**直接对单辆车（按 VIN）维护物流信息**——不再组织运输单、发车清单等批量单据。功能因此更简单：物流两段回归为「按 VIN 逐车维护 → 确认 → 推进生命周期」，与生产/销售/财务等其他阶段完全同构。

**关键前提：两套运输管理共存、互不影响、各自独立。** D00001 的需求维持现状，之前设计的单据式表（运输单 / 发车清单 / 行车路单 / 经销商行等 6 张表）与后端代码/API 全部继续保留，但其功能**不再使用**；运输管理的**入口切换**为新设计的按 VIN 功能。因此系统中同时存在两套运输管理实现，共享同一 `t_vehicle` 与生命周期，但旧入口停用后仅新功能在实际使用。

## 需求要点

1. **按 VIN 单车维护**：车厂→中转仓库（入库）、中转仓库→经销商（配送）两段物流，均以单辆车为操作单位，输入 VIN（或从待办列表选车）后维护该车的物流字段。
2. **两套共存、各自独立**：新的按 VIN 功能与旧的单据式运输管理**并存、互不影响**。旧单据表与后端代码/API 全部保留不删，仅停用旧功能；运输管理入口切换为新功能。
3. **旧功能停用 = 仅隐藏菜单入口**：旧单据式的表、后端代码、API 均保留可用，只从菜单移除/隐藏其入口，日后可快速恢复。
4. **保留确认锁定机制**：沿用 D00001「草稿可改 → 确认锁定 → 推进 lifecycle_stage」的统一交互；确认后本阶段数据不可再改、不可重复确认；记录确认人/确认时间。
5. **共享同一生命周期**：两套共享同一 `t_vehicle` 与同一套生命周期卡控；旧入口停用后仅新功能推进，不冲突。
6. **生命周期不变**：7 阶段顺序与卡控规则完全不变，仅物流两段的**操作方式**从「单据整单/按行确认」改为「按 VIN 单车确认」。
7. **不建仓库实体**：中转仓库沿用 D00001 处理方式，不引入仓库主数据/实体，仅记录「到仓日期」等字段。

## 关键决策（已与用户确认）

| 决策点 | 结论 |
|--------|------|
| 与原方案关系 | 两套运输管理**共存、各自独立、互不影响**；旧单据表全部保留，运输管理入口切换为新功能 |
| 旧功能停用方式 | 仅隐藏/移除旧菜单入口；旧表、后端代码、API 保留可用，可快速恢复 |
| 生命周期共享 | 两套共享同一 `t_vehicle` 与生命周期卡控；旧入口停用后仅新功能推进 |
| 确认机制 | 保留 D00001「草稿→确认锁定→推进」，改为按 VIN 单车确认 |
| 中转仓库 | 沿用 D00001，不建仓库实体，仅记录到仓日期等字段 |
| 生命周期 | 7 阶段顺序与卡控不变，仅改物流两段操作粒度 |
